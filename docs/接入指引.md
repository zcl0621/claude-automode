# 接入指引

## 1. 准备

- Claude Code。开发和测试用的是 v2.1.332
- `python3`（3.8 及以上，只用标准库）
- 一个分类器模型的 API，兼容 OpenAI `/chat/completions` 或 Anthropic `/v1/messages` 的都可以

分类器最好和 agent 用不同的模型，免得一段注入同时骗过两个。

## 2. 安装

在 Claude Code 里添加插件市场，然后安装：

```
/plugin marketplace add zcl0621/claude-automode
```

```
/plugin install automode@claude-automode
```

也可以不安装，直接从本地目录加载：

```bash
git clone https://github.com/zcl0621/claude-automode.git
```

```bash
claude --plugin-dir ./claude-automode/plugin --permission-mode acceptEdits
```

## 3. 配置分类器

有三种方式，后面的会覆盖前面的。

### 方式一：插件配置项（推荐）

装好插件后，在 Claude Code 里运行：

```
/plugin configure automode@claude-automode
```

非密钥的几项也会出现在 `/config` 里。安装时也可以直接带上，例如 `claude plugin install automode@claude-automode --config slow_model=deepseek-flash`。

配置项：

| 项 | 说明 |
|---|---|
| Classifier API format | `openai` 或 `anthropic` |
| Classifier base URL | 例如 `https://api.deepseek.com` |
| Classifier API key | 存在系统的安全存储里 |
| Classifier model (stage 2, required) | 给出 allow / deny / ask 结论的模型，必填 |
| Fast filter model (stage 1, optional) | 先过滤明显低风险调用的便宜模型，可以不填 |
| Send thinking: disabled | 默认会思考的模型（比如 DeepSeek）要打开，否则输出又慢又啰嗦 |

hook 每次运行时读取这些值。改完之后要不要重启会话才生效，我没验证过，保险起见可以重启一次。

### 方式二：配置文件

写到 `~/.claude-automode/config.json`。字段名和 `plugin/scripts/automode/config.py` 里的 `Config` 一样：

```json
{
  "provider": "openai",
  "base_url": "https://api.deepseek.com",
  "api_key": "你的 key",
  "fast_model": "deepseek-flash",
  "slow_model": "deepseek-flash",
  "fast_extra": {"thinking": {"type": "disabled"}},
  "slow_extra": {"thinking": {"type": "disabled"}},
  "slow_max_tokens": 300
}
```

这个文件里有密钥，记得设权限：

```bash
chmod 600 ~/.claude-automode/config.json
```

`/config` 里没有的选项也能在这里设：

| 字段 | 默认 | 说明 |
|---|---|---|
| `fast_extra` / `slow_extra` | `{}` | 原样合并进请求体，用来传服务商特有的参数 |
| `slow_max_tokens` | 4096 | 第二阶段的输出上限。关了思考的话 300 就够 |
| `timeout_s` | 30 | 单次请求超时，超时就弹窗 |
| `max_consecutive_denials` | 3 | 连续拒绝超过这个次数，就改成弹窗 |
| `user_message_limit` | 12 | 分类器能看到你最近几条消息 |
| `log_inputs` | true | 日志里要不要记截断后的工具参数 |

### 方式三：环境变量

`AUTOMODE_PROVIDER`、`AUTOMODE_BASE_URL`、`AUTOMODE_API_KEY`、`AUTOMODE_FAST_MODEL`、`AUTOMODE_SLOW_MODEL`、`AUTOMODE_FAST_EXTRA`、`AUTOMODE_SLOW_EXTRA`（JSON），等等。完整列表见 `config.py` 里的 `ENV_MAP`。

## 4. 选权限模式

Claude Code 的权限模式是固定的几种，没法新增。这个插件挂在弹窗这一步，所以要选一个"会弹窗"的模式：

| 模式 | 能不能用 | 说明 |
|---|---|---|
| `acceptEdits` | **推荐** | 项目内的文件编辑由 Claude Code 自己放行，其余要弹窗的都交给插件 |
| `default` | 可以 | 文件编辑也会交给插件判断，调用模型的次数更多 |
| `plan` | 没测过 | 计划阶段基本只读 |
| `auto` | 不适用 | 原生 auto mode 只支持 Claude 模型 |
| `bypassPermissions` | 不适用 | 不弹窗，插件拿不到任何调用 |
| `dontAsk` | 不适用 | 不弹窗，没预先允许的直接拒绝 |

启动：

```bash
claude --permission-mode acceptEdits
```

只在交互式会话里用。`claude -p` 下 ask 会被当成拒绝。

## 5. 它怎么回应

| 判断结果 | 你看到的 |
|---|---|
| allow | 不弹窗，直接执行 |
| deny | 不弹窗。agent 收到 `[automode] denied: <原因>`，会换个做法 |
| ask、出错、超时 | 照常弹窗，由你决定 |
| 连续 deny 超过 3 次 | 照常弹窗 |

另外，每次工具调用结束后，插件会扫描输出。发现注入内容时，会给 agent 加一条提醒，类似 `[automode] The output of ... appears to contain instructions planted for the agent`。

## 6. 看日志

每次判断都会追加一行到 `~/.claude-automode/decisions.jsonl`，包括工具名、结论、哪一步做的决定（`rules` / `fast` / `slow` / `error`）、原因和耗时。

想看被拒和弹窗的记录：

```bash
grep -v '"decision": "allow"' ~/.claude-automode/decisions.jsonl | tail -20
```

## 7. 常见问题

**装上了却从来不触发？**
- 确认用的是 `acceptEdits` 或 `default` 模式
- 你在 settings 里 allow 过的命令不会弹窗，所以也不经过插件
- 用 `claude --debug` 看 hook 有没有运行

**每次都弹窗？**
- 看日志的 `stage`。是 `error` 的话，`reason` 里会写原因，常见的是 key 不对、模型名不对、余额不足
- 用 DeepSeek 时记得打开 "Send thinking: disabled"，否则第一阶段的输出预算会被思考过程用完

**想让某类命令永远直接放行？**
用 Claude Code 自己的 permissions allow 规则，比插件判断更快，也不花钱。
